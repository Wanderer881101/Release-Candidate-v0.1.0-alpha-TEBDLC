# TEBDLC v0.1.0-alpha — Public Release Doctrine

Status: **ACTIVE / SUPERSEDING PUBLICATION DOCTRINE**

Effective decision: 2026-08-21 (America/Montreal)

## 1. Purpose

This record resolves the publication-doctrine conflict identified during assembly of the public Release Candidate.

The `Release-Candidate-v0.1.0-alpha-TEBDLC` repository is intended to contain a complete, usable and verifiable public TEBDLC Release Candidate, including the material required for its operation and independent verification: source code selected for the Release Candidate, build components, tests, vectors, evidence, documentation, reproducibility resources and other dependencies intentionally included in the assembled public product.

## 2. Supersession rule

Earlier documents that describe `v0.1.0-alpha` exclusively as a controlled-distribution release in which the complete usable source package must remain outside the public repository are preserved as historical records, but that publication doctrine is **superseded for this public Release Candidate** by this document.

This specifically applies to conflicting publication-boundary statements in documents including:

- `RELEASE_GATE_v0.1.0-alpha.md`;
- `RELEASE_NOTES_v0.1.0-alpha.md`;
- `PUBLICATION_RECORD_v0.1.0-alpha.md`.

Those files are not deleted or silently rewritten. They remain available to preserve the chronology, prior decisions, hashes, validation records and historical controlled-distribution work.

Where one of those historical documents conflicts with this document solely on whether the assembled usable Release Candidate may be public, this document governs the current public Release Candidate.

## 3. What is not superseded

Supersession of the old publication boundary does not automatically invalidate unrelated historical facts, validation results, provenance records, intellectual-property notices, licence terms, territorial-policy records, hashes, test results or evidence contained in earlier documents.

Each such statement retains its own evidentiary status unless separately revised, contradicted by newer evidence, or explicitly superseded.

## 4. Preservation invariant

No historical document, validated gain, evidence record or source component is to be deleted merely because the publication doctrine changed.

Changes required to reconcile the public Release Candidate must be additive or explicitly versioned whenever practicable, preserving reconstruction of the previous state.

## 5. Public product invariant

The public Release Candidate must remain materially usable and independently verifiable. A publication-cleaning operation must not remove a source file, component, dependency description, test, vector, proof, evidence artifact or reproducibility mechanism merely because it is technical or implementation-bearing when that material is required for the intended public product or its verification.

Material that is genuinely secret, credential-bearing, personal, legally restricted, unrelated private material, or explicitly outside the approved Release Candidate remains outside this doctrine and requires a separate inclusion decision.

## 6. Intellectual property

Public availability does not by itself place TEBDLC in the public domain or convert it to an open-source licence. Rights remain governed by the active TEBDLC licence, notices and applicable law.

## 7. Release lineage

The current assembly branch is `release-v0.1.0-alpha-readme-notice`.

The doctrine recorded here authorizes reconciliation of publication documentation around the assembled public-product model. It does not by itself authorize deletion of historical files or destructive rewriting of repository history.
